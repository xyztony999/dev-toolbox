# D0 需求澄清 — 项目上下文

日期：2026-10-27。模块：`project-context`。性质：已结合初始化方向与静态证据形成的设计输入；范围限于只读发现，不包含运行时切换或身份写入。

## 目标与用户

开发者需要把日常工作集合登记到 DevToolbox，并看清其中 Git 工作树、独立构建模块以及这些模块声明的运行时要求。项目、仓库和模块不是一对一关系；扫描必须说明每条判断来自哪个文件、置信度如何，无法判断时保留 unknown。

## 业务概念

| 概念 | 本模块中的含义 |
|---|---|
| Project | 用户登记的工作集合，可含多个路径、仓库和构建模块 |
| Repository | Git 识别的工作树，包含普通仓库、worktree 与嵌套仓库 |
| Module | 由独立构建清单或明确项目结构识别的子路径 |
| RuntimeRequirement | 从静态声明提取的运行时名称、原始约束、来源文件及解析状态 |
| Evidence | 文件路径、字段/声明、原文摘要及解析器版本组成的发现证据 |

## 主要流程

1. 用户选择目录并发起扫描；扫描只读取允许的目录项和已支持的清单文件。
2. 系统展示候选仓库、模块、声明的版本要求及来源证据。
3. 用户确认登记结果；登记保存项目关联，不改写清单、不运行脚本或 Wrapper。
4. 用户可重新扫描；结果按证据来源更新，并保留未知、冲突和无法读取状态。

## 范围

- 做：项目登记/移除；只读扫描；仓库、模块及 Node/Python/Java/Go/Maven/Gradle/Android SDK 声明识别；证据来源展示；重扫。
- 不做：安装/下载/切换运行时、执行项目命令、修改 PATH/注册表/shell profile、Git 身份应用、迁移旧应用数据、Docker/数据库生命周期管理。
- 角色：本机开发者（发起扫描、确认登记、查看发现结果）。无账号、服务端或多租户。

## 澄清决策

- 依据 `docs/merge-direction.md`：项目/仓库/模块分离；unknown 与冲突需明确呈现。
- 依据业务规则：Git 事实交由 Git 解析，但扫描不得为发现而运行任意项目脚本；目录归属与工作树识别可读取 Git 元数据。
- 依据安全基线：扫描只读；不读取 `.env`、凭据文件或依赖目录；不跟随越界符号链接。
- 本模块的登记保存位置及跨平台路径规范归 D3 定义；共享版本要求与本机绑定分开。

## 待后续模块处理

运行时安装与作用域应用属于 `runtime-migration`；Git 身份与配置审计属于 `git-identity-migration`；旧数据导入属于 `diagnostics-and-compatibility`。本设计不预设其接口或数据 schema。
