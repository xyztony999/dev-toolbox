# D0 需求澄清 — 本机运行时发现与登记

版本：v1.0 | 日期：2026-10-27 | 模块：runtime-migration

## 来源匹配与范围

- 完全匹配：七工具目录和用户级默认状态；已由 `user-runtime-state-migration` 保留 `current` 与 `runtimes`。
- 部分匹配：DevSwitch 的本机扫描、手动导入和当前选择页面在新产品已有 UI/模型雏形，但没有真实本机扫描服务。
- 本轮新增切片：只读发现本机现存安装，展示候选后由用户明确登记；登记后可通过既有全局默认动作选择。
- 后续独立设计：网络下载/安装、shim 与 PATH、shell hooks、项目/会话覆盖、生效与恢复。

## 已确认的用户与业务规则

- 用户：本机开发者；不涉及账号、服务端或跨设备同步。
- 工具：Node、Java、Maven、Gradle、Android SDK、Go、Python。
- 扫描来源：当前进程 PATH 中的已知可执行文件、常见系统安装根，以及用户明确指定的目录；不递归扫描整盘。
- 发现阶段只读文件系统、PATH 和平台注册信息；不启动候选二进制，不运行项目脚本、Wrapper、hook 或下载器。
- 候选结果在确认登记前不进入用户状态；登记只写 DevToolbox 数据，不复制或移动安装目录。
- 用户级全局选择和项目/会话覆盖相互隔离；本切片不改 PATH、注册表或 shell profile。
- 版本无法由静态元数据可靠识别时显示 unknown，不能推断 latest 或替用户执行版本命令。

## 核心实体与关系

RuntimeCandidate 经静态识别和用户确认后产生 RuntimeInstallation；GlobalRuntimeSelection 指向已登记安装。缺失路径的旧选择仍保留为 unresolved，不由扫描自动替换。RuntimeRequirement 属于项目声明，本切片仅保留兼容关系，不据此自动切换。

## 主要流程

刷新发现 → 合并重复候选并显示来源/版本置信度/路径 → 用户选择候选并确认登记 → 刷新用户级清单 → 用户可显式设置全局默认。取消或扫描失败不写用户状态。

## D0 边界

目前约束足以进入设计；未确认的安装 provider、自动下载、自动切换及 shell 集成不纳入本轮承诺。
