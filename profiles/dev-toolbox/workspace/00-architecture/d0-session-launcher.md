# D0 需求澄清 — 会话启动器

版本：v1.0 | 日期：2026-11-03 | 模块：session-launcher

## 来源与定位

merge-direction 第二批核心："从项目视图打开指定上下文的终端/子进程；多个项目同时运行时互不切换全局默认"。这是让"项目该用什么环境"从**可见**变成**可直接用上**的闭环一步（方向讨论中列为优先级第 2）。

## 能力基线

| 能力 | 语义 | 边界 |
|---|---|---|
| 上下文计算 | 按用户级 GlobalRuntimeSelection（八工具）求值每工具生效安装：可用 → 注入；未选择/不可用 → 如实标注"未注入（用系统默认）" | 只读 |
| 环境注入 | PATH 前置所选运行时 bin 目录；java 另设 JAVA_HOME；其余 HOME 类变量后续按需 | 仅注入启动的子进程 |
| 终端枚举 | Windows：PowerShell、cmd、Git Bash（检测到才列出）；Linux：$SHELL 回退 bash | 只列真实可用的 |
| 启动会话 | 在选定 cwd（项目根/仓库根）以注入环境启动新终端窗口；多会话并存互不影响 | 用户显式动作 |
| Git 身份预览 | 预览显示该 cwd 的生效身份（来自既有解析），不注入任何 git 配置 | 展示不写 |

## 已确认规则（对齐 ADR-007 与产品纪律）

1. 会话环境**只作用于启动的终端进程**：新进程 env = 父环境 + 注入项；绝不写用户/系统环境变量、注册表、shell profile，不改任何已打开终端（GUI 无法改写父 shell，不承诺）。
2. 不改全局默认：启动会话不触碰 GlobalRuntimeSelection；多项目多会话并存。
3. 终端窗口由用户显式点击启动；启动失败（终端找不到）如实报错码。
4. cwd 默认项目根，可选项目内仓库根；非存在目录拒绝。
5. Git 身份在会话中的生效仍由 git 自身机制（仓库本地/includeIf/全局）决定；本模块只在预览中展示，不写配置。
6. Windows 首版直接启动 powershell/cmd/bash 独立控制台窗口；Windows Terminal（wt 单实例转发 env 语义复杂）与"在上下文中运行任意命令"列入暂不纳入。

## 暂不纳入

任意命令执行、Windows Terminal 集成、shim/JAVA_HOME 等会话外刷新（归"可靠应用"批次）、tmux/SSH 远程会话、会话生命周期跟踪（记录/终止已启动终端）。
