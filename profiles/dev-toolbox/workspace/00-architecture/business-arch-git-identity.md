# 业务架构 — Git 身份管理

版本：v1.0 | 日期：2026-10-28 | 模块：git-identity-migration

## 1. 业务域与活动

归属支撑业务域。用户在多套个人/团队 Git 身份间切换，避免"用公司邮箱提交了个人仓库"。

| L3 关键业务 | L4 业务活动 | 输入 | 输出 | 边界 |
|---|---|---|---|---|
| 身份档案 | 维护身份档案 | id、姓名/邮箱/签名键/格式、重写、账号选择器 | IdentityProfile 清单 | 不存 token；重复 add 为覆盖更新 |
| 身份档案 | 收编现有身份 | 当前全局配置或扫描 ⚠ 发现 | 新档案 | 预览+确认；不改原配置 |
| 身份应用 | 应用/清除身份 | id、作用域（全局/仓库/多仓）、dry-run | 每键写入/清除计划或结果 | 全量覆盖；git 是事实源 |
| 身份应用 | 查看生效身份 | 目录或仓库路径 | 生效 id 与每键来源 | 只读解析 |
| 目录绑定 | 绑定/解绑目录树 | id、目录 | includeIf 钩子 + 托管片段 | 解绑回收前检测手改漂移 |
| 仓库审计 | 扫描仓库身份 | 根目录、深度 | 逐仓身份与镜像状态 | 只读；不运行项目命令 |
| 仓库审计 | 提交审计 | 仓库、期望身份、strict | 作者分布、污染标注、mailmap 建议 | 不写 .mailmap；strict 是门禁非修复 |
| 环境体检 | Git 体检 | 本机环境 | 版本/凭据/重写冲突/绑定健康 | 只读不修复 |
| 镜像与凭据 | 管理镜像推送 | 仓库、镜像 URL | 多 pushurl 配置 | 不影响 fetch 与凭据通道 |
| 镜像与凭据 | 凭据账号选择 | host、用户名 | credential 协议直通 | token 不经手不回显 |
| 档案迁移 | 导入 gitid 档案 | 旧 config.json | 预览/备份/幂等导入记录 | 旧文件只读不动 |

## 2. 业务规则

- 应用=全量覆盖：档案缺失的受管键被清除，不残留前一身份；重写与账号选择器随应用生效、随切换清理。
- dry-run 与真实执行同一算法，只算不写；批量应用允许部分失败并逐仓如实汇报。
- 生效判断以 git 自身输出为准；本地覆盖优先于目录绑定，目录绑定优先于全局。
- 凭据 token 只经 git credential 协议进 helper；服务不留存、不回显、不写日志。
- 旧档案导入预览+备份+来源摘要幂等；不与 gitid 同时写旧文件。
