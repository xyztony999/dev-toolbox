# 业务架构 — DevToolbox（全局）

版本：v2.0 | 日期：2026-11-11 | 状态：全局重划，基于 9 个已交付模块的实现事实

> v1.0 只展开"项目上下文"一个支撑域。v2.0 按当前全部已交付能力重划全局业务架构；模块级 BA 文档（workspace/00-architecture/business-arch-*.md）继续作为各切片的详细展开，本文档是它们的上层聚合。

## 1. 产品业务域（L1）

DevToolbox：本机开发环境与 Git 身份管理工具箱——让开发者"打开项目即知、即用正确的运行时与 Git 身份"。

单一用户角色：本机开发者（无多租户/服务端）。

## 2. 业务阶段（L2，按用户工作流主线）

| # | 阶段 | 业务定位 | 用户问题 |
|---|---|---|---|
| 1 | 认识项目 | 建立项目/仓库/模块与版本要求的项目上下文 | "这个项目是什么结构、要什么环境？" |
| 2 | 准备环境 | 备齐运行时与身份资产（安装/登记/档案/凭据） | "本机有没有、缺什么、身份对不对？" |
| 3 | 连接协作 | 仓库与目录的协作配置（remote/镜像/身份绑定） | "怎么推到多个远端、目录怎么自动用对身份？" |
| 4 | 进入工作 | 把准备好的环境应用为可工作的会话 | "给我一个环境正确的终端" |
| 5 | 保持健康 | 体检与历史资产迁移 | "哪里坏了？旧工具的数据怎么接过来？" |

## 3. 关键业务与活动（L3/L4）

### 阶段 1：认识项目

| L3 关键业务 | L4 业务活动 | 边界 | 来源模块 |
|---|---|---|---|
| 项目上下文管理 | 登记项目 / 发现仓库与模块 / 核对版本声明 / 读取仓库 Git 信息 / 刷新与移除 | 只读扫描；不运行项目命令 | project-context |

### 阶段 2：准备环境

| L3 关键业务 | L4 业务活动 | 边界 | 来源模块 |
|---|---|---|---|
| 运行时发现与登记 | 本机扫描 / 指定目录检查 / 显式确认登记 / 外部工具链导入（rustup/uv） | 零执行被检程序；不夺管理器所有权 | runtime-migration, toolchain-import |
| 运行时获取安装 | provider 查询 / 计划预览 / 确认下载安装 / 取消与重试 | 只写自有目录；校验与安全解包强制 | runtime-download-install |
| 用户级全局默认 | 全局默认查询与显式设置 / DevSwitch 状态迁移导入 | 项目/会话不得隐式改写全局 | user-runtime-state-migration |
| Git 身份档案 | 档案 CRUD / 收编全局或手配身份 / 档案迁移（gitid） | token 不入档案；git 为事实源 | git-identity-migration |
| 凭据通道 | 账号选择器管理 / helper 登录 / 凭据写入与擦除 | token 只经 credential 协议直通 | git-identity-migration |

### 阶段 3：连接协作

| L3 关键业务 | L4 业务活动 | 边界 | 来源模块 |
|---|---|---|---|
| 仓库 remote 管理 | remote 列表/增删/改名/改地址 | 名字与 URL 白名单防注入 | git-remote-management |
| 镜像推送 | pushurl 双目标开启与取消 | fetch 与凭据通道不受影响 | git-identity-migration, git-remote-management |
| 目录身份绑定 | 目录树绑定 / 解绑 / 漂移警告 | includeIf 机制；片段托管可回收 | git-identity-migration |

### 阶段 4：进入工作

| L3 关键业务 | L4 业务活动 | 边界 | 来源模块 |
|---|---|---|---|
| 上下文求值 | 八工具逐项求值（注入/未注入及原因）/ 生效身份预览 | 只读；如实呈现不静默回退 | session-launcher |
| 会话启动 | 终端枚举 / 注入环境启动新终端 | 注入仅子进程树；零持久写 | session-launcher |

### 阶段 5：保持健康

| L3 关键业务 | L4 业务活动 | 边界 | 来源模块 |
|---|---|---|---|
| Git 体检 | 版本/凭据助手/重写冲突/绑定健康检查 | 只读；不自动修复 | git-identity-migration |
| 仓库审计 | 逐仓身份扫描 / 提交作者审计（strict 门禁） | 不写 .mailmap；不执行项目命令 | git-identity-migration |
| 遗留资产迁移 | DevSwitch 状态 / gitid 档案 / 手配身份收编 | 预览+备份+幂等；旧文件只读 | user-runtime-state-migration, git-identity-migration |

## 4. 业务规则（全局不变量）

1. Git 实际配置与运行时生效状态均以原生机制为事实源；产品只在显式用户动作时写入。
2. 全局默认、系统 PATH、注册表、shell profile 不被项目/会话/安装隐式修改。
3. 凭据 token 不落档案、不进日志与广播。
4. 扫描与体检只读；跨模块操作结果区分成功/失败/跳过，不伪装原子事务。
5. 外部工具链管理器（rustup/uv/DevSwitch）的所有权不被夺取。
6. 单一本机开发者角色；无跨用户共享语义。

## 5. 业务依赖

文件系统与 Git 元数据是项目域输入事实；用户级清单（运行时安装/选择、身份档案）是准备阶段的资产事实；会话求值只消费上述事实，不新增事实源。
