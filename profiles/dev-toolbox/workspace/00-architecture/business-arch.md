# 业务架构 — DevToolbox（项目上下文范围）

版本：v1.0 | 日期：2026-10-27 | 状态：D1 初稿，供 Gate 1 校验

## 1. 产品业务域

DevToolbox 是本机开发环境与 Git 身份管理工具。此文档只展开“项目上下文”支撑域，为后续运行时、Git 身份和诊断能力提供稳定的项目/仓库/模块视图。

## 2. 业务阶段

| 阶段 | 业务活动 |
|---|---|
| 建立上下文 | 登记工作集合、扫描目录、确认仓库与模块 |
| 维护上下文 | 重扫并检查证据变化、移除项目登记 |
| 查看上下文 | 浏览项目、仓库、模块、版本声明和未知/冲突状态 |

## 3. 关键业务与活动

| L3 关键业务 | L4 业务活动 | 输入 | 输出 | 边界 |
|---|---|---|---|---|
| 项目上下文管理 | 登记项目目录 | 用户选择的本机目录 | Project 登记 | 不复制目录内容 |
| 项目上下文管理 | 发现仓库与模块 | 登记根目录下的静态文件与 Git 元数据 | Repository/Module 候选 | 不运行命令或脚本 |
| 项目上下文管理 | 核对运行时声明 | 支持的清单/配置文件 | RuntimeRequirement 与 Evidence | 不判断本机已安装状态 |
| 项目上下文管理 | 刷新/移除登记 | 已登记项目 | 更新结果或移除结果 | 不删除用户项目文件 |

## 4. 业务规则

1. Project、Repository、Module 分别建模，可多对多关联。
2. 扫描结果必须保留来源与原始约束；解析不确定或多来源冲突时不得猜测。
3. 普通仓库、worktree、嵌套仓库均需独立识别。
4. 扫描只读；未知格式、权限拒绝、循环链接以可见状态返回。
5. 登记/移除只影响 DevToolbox 自有数据，不改用户目录。

## 5. 业务依赖

本地文件系统与 Git 元数据是输入事实。运行时安装目录、全局默认、Git 作者身份均不属于本域的事实源。
