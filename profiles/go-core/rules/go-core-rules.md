# Go 核心工程规范

- GC-01：领域与应用服务不依赖 WebView、Vue 或 GUI 事件循环；CLI 和 GUI 使用同一服务。
- GC-02：平台差异通过小型 OS 适配器与 build tags 隔离；无 GUI 构建不能隐式引入 CGO 桌面依赖。
- GC-03：外部进程使用参数数组、context 超时/取消和明确工作目录；禁止拼接 shell 命令、继承敏感输入到日志。
- GC-04：文件写入与状态更新采用原子替换/锁等明确并发协议；公开可测试的路径与进程依赖注入点。
- GC-05：业务副作用测试使用沙箱与适配器；模拟 git/helper，不能默认调用真实用户配置或改系统环境。
- GC-06：耗时扫描、下载和安装可取消，错误包含稳定分类与作用域，输出不泄露凭据。
- GC-07：接口改动需要完整副作用和失败路径回归；迁移使用行为对比，覆盖来源核心不变量。
- GC-08：实现后必须 gofmt、go vet ./...、go test ./... 与 go build ./...；GUI 使用独立 tag 验证，不能用静态 CLI 构建冒充 GUI 通过。
- GC-09：编译器/依赖版本在真实 go.mod/go.sum 中锁定；不存在源码或依赖时报告未执行，不伪造通过。

构建命令以仓根为工作目录；代码根来自业务 slots.code_root，默认 `.`。本规范不要求机器级环境变量。
